## แล็บนี้คืออะไร

DL-05 ให้หาว่าระบบ LLM/RAG เจอปัญหาอะไรบ้าง และแก้อย่างไร ต้นแบบของรายวิชาตอบคำถามนี้ด้วย
การจำลองเก้าแบบที่แยกกันอยู่ — `bad_generate()` ที่คืนคำโกหกซึ่งเขียนตายตัวไว้แล้ว,
ข้อความสกปรกที่ถูกสร้างขึ้นสองบรรทัดก่อนจะทำความสะอาด, เอกสารสมมติ "ที่อันดับ 8"
ซึ่งไม่ได้คำนวณจริง ทั้งหมดอธิบายแนวคิดได้ชัด แต่ไม่มีอันไหนพังได้เลย เพราะความพังถูกเขียนลงไปในสคริปต์เอง

โฟลเดอร์นี้ตอบคำถามเดียวกันด้วยปัญหาที่เกิดขึ้นจริง ทุกโมดูลคือข้อผิดพลาดหรือผลวัดจาก LAB1–LAB3 —
บั๊กที่ทำให้ระบบพัง, ตัวเลขที่ออกมาสวนทางกับที่คาด, หรือผลลัพธ์ที่กลายเป็นว่าวัดผิดเรื่อง —
เขียนให้รันซ้ำได้ พร้อมวิธีแก้อยู่ข้าง ๆ

| | ต้นแบบ | ที่นี่ |
|---|---|---|
| ข้อมูล | `sex_q_a.txt` คัดลอกเข้ามาไว้ในโฟลเดอร์ | อ่าน `LAB3/RAG-Project/data/scam_q_a.txt` ตรงที่มันอยู่ — มีสำเนาเดียวในรีโป |
| ความพัง | เขียนด้วยมือไว้ในตัวเดโมเอง | หยิบมาจาก LAB1–LAB3 เขียนซ้ำจากโค้ดที่เคยมีบั๊กนั้นจริง |
| ตัวเลข | เล่าเป็นคำบรรยาย | โหลดจากไฟล์ `eval_*.json` ที่วัดได้จริงและ commit ไว้แล้ว |

## วิธีรัน

```bash
cd LAB4
python main.py          # เมนู
python main.py 7        # เลือกปัญหาเดียว
python main.py 0        # ทั้งสิบข้อ ประมาณ 1000 บรรทัด
```

ใช้แค่ standard library ไม่ต้องมี LLM, GPU, ไม่ต้องโหลดโมเดล และไม่ต้อง `pip install` —
ตัวเลขที่วัดได้ถูกอ่านจาก JSON ที่ LAB3 เขียนไว้ ไม่ได้คำนวณใหม่ ใช้ Python 3.9 ขึ้นไป

`data_loader.py` หาไฟล์ของ LAB1 และ LAB3 ด้วย relative path ดังนั้น LAB4 ต้องอยู่ข้าง ๆ แล็บเหล่านั้น
ในรีโปนี้ ถ้าไฟล์ไหนหาย จะขึ้น `MissingArtefact` พร้อมบอกคำสั่งที่ใช้สร้างไฟล์นั้น
แทนที่จะเป็น `FileNotFoundError` บน path ที่ไม่มีใครจำได้

## สามข้อที่ควรอ่านก่อน

**fallback ที่เงียบร้ายกว่าการมั่ว** (ข้อ 1) — คีย์ตัวอย่างของ Ollama คือสตริง `"ollama-ไม่ใช้-key"`
ซึ่งถูกใส่ลงใน header `Authorization` และ OpenAI SDK เข้ารหัส header เป็น ASCII
การเรียกจึงพังตั้งแต่ก่อนออกจากเครื่อง — ทุกครั้ง แต่ `Generator.generate()` ดักทุก exception
แล้วคืน `chunks[0]["answer"]` โดยบรรทัด warning ถูกคอมเมนต์ไว้ ผลคือ `USE_LLM = True`
คืนข้อความดิบที่ค้นได้ แต่รายงานตัวเองว่าเป็นคำตอบที่โมเดลเขียน การมั่วยังพอจับได้ แต่อันนี้จับไม่ได้เลย

**เกณฑ์วัดผลผ่านได้ตั้งแต่ตอนสร้าง** (ข้อ 9) — `build_golden_set.py` สร้างคำถามทุกรูปแบบจากคำถามต้นฉบับ
ด้วยการต่อสตริง เช่นรูปแบบ `natural` คือคำถามเดิมที่เติม `สงสัยว่า` ข้างหน้าและ `ยังไงคะ` ข้างหลัง
วัดในโมดูลนี้ได้ว่าทุกรูปแบบยังเหลือตัวอักษรของเป้าหมายอยู่ 92–100 % BM25 จับคู่ที่ระดับโทเคน
จึงได้ MRR 0.9933 และดูเหมือนชนะ cross-encoder ขนาด 568M พารามิเตอร์
นั่นเป็นข้อเท็จจริงเกี่ยวกับตัวเกณฑ์วัด ไม่ใช่เกี่ยวกับ BM25

**โมเดลที่ถูกจูนด้านความปลอดภัยจะไม่ยอมเขียนกลโกง** (ข้อ 10) — HyDE สั่งให้โมเดลแต่งคำตอบที่ดูสมเหตุสมผลขึ้นมา
แต่ฐานความรู้นี้ว่าด้วยกลโกงทำงานอย่างไร `llama3.1:8b` จึงอ่านคำสั่งนั้นเป็นการขอให้ช่วยไปหลอกคนอื่น
18 จาก 68 prompt กลับมาเป็นคำขอโทษ และ `query_transform.py` ไม่มีทางแยกคำขอโทษออกจากคำตอบ
คำขอโทษจึงถูกส่งไปให้ตัวค้นหาเป็นคำค้น นี่คือรูปแบบความล้มเหลวจริงของ HyDE บนเนื้อหาที่อ่อนไหว
และมองไม่เห็นเลยถ้าไม่ log ว่าคำค้นจริง ๆ คืออะไร

## ข้อบกพร่องสองอย่างที่แล็บนี้หาเจอเอง

ทั้งสองอย่างเจอเพราะเขียนโค้ดตรวจจริง ไม่ใช่เพราะเดาว่าข้อมูลสะอาด และทั้งสองอย่าง**รายงานไว้ ไม่ได้แก้**

- **คู่ที่เกือบซ้ำกัน 5 คู่ใน `scam_q_a.txt`** (ข้อ 3) — ทุกคู่คือรูปแบบภาษาแสลงที่ถูกคัดลอกมาจากภาษากันเอง
  แล้วแก้ไปหนึ่งถึงสองคำ แทนที่จะเขียนใหม่ คำถามเหมือนกัน 96.6–100 % คำตอบเหมือนกัน 96.2–100 %
  การตรวจแบบ exact match เจอเพียง 1 ใน 5 คู่ เรื่องนี้สำคัญกว่าแค่ความเรียบร้อย เพราะรูปแบบภาษาแสลง
  คือตัวที่ควรจะทดสอบว่าการค้นคืนยังรอดไหมเมื่อคำไม่คุ้น แต่คำถามแสลงที่เหมือนคู่แฝดภาษากันเอง 97 %
  ไม่ได้ทดสอบเรื่องนั้นเลย
- **chunk ท้าย 13 ชิ้นที่ไม่มีคำถาม** (ข้อ 4) — `split_text()` ตัดสตริง `"Question: … Answer: …"`
  ตามตำแหน่งตัวอักษร ชิ้นแรกเท่านั้นที่ได้คำถามติดไป chunk ท้ายทุกชิ้นจึงเป็นเศษข้อความยาว
  54–104 ตัวอักษร ที่ถูกแปลงเป็นเวกเตอร์โดยไม่มีอะไรบอกว่ามันตอบคำถามอะไร

ที่ไม่แก้ตรงนี้เป็นความตั้งใจ การแก้ `scam_q_a.txt` หรือแก้ตัวตัด chunk จะทำให้ FAISS และ BM25 index
ที่ commit ไว้ใช้ไม่ได้ พร้อมกับตัวเลขทุกตัวใน `outputs/` ซึ่งคือความล้มเหลวแบบเดียวกับที่ข้อ 5 พูดถึง
วิธีแก้ที่ถูกคือแก้ข้อมูลและ build index ใหม่เป็น commit เดียวกัน พร้อมรันประเมินผลใหม่ —
ซึ่งต้องใช้ชุดโมเดลที่โฟลเดอร์นี้ตั้งใจไม่พึ่งพา
